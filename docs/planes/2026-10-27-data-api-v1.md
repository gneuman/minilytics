## Objetivo

Exponer un **API de datos sobre `/api/v1`** para que Gabriel y sus agentes de IA puedan **leer las
métricas de minilytics desde fuera** (sin el login del dashboard) y **empujar métricas externas**
(ej. impresiones de un post de LinkedIn) junto al tráfico, para tomar mejores decisiones de
publicación.

Decisiones de diseño:
- **Auth:** API key por sitio (reusar `sites.api_key`, header `Authorization: Bearer ml_...`),
  consistente con la ingesta ya existente (`/api/v1/payments`, `/api/v1/goals`).
- **Enriquecimiento:** endpoint genérico de eventos (`POST /api/v1/events`), no que minilytics jale
  APIs externas por su cuenta (eso queda para una segunda vuelta con OAuth).
- **Eventos externos sin visitante:** visitante sintético `ext:<plataforma>` + sesión sintética
  (no toca el schema `NOT NULL`, quedan agrupables por plataforma).

## Lo que se hizo

Todo bajo `Authorization: Bearer ml_<api_key del sitio>`:

- `GET /api/v1/summary` — snapshot AI-ready: KPIs (actual vs periodo previo) + top sources/channels/
  entry pages por revenue, en unidades mayores. Compone `overview()` + `breakdown()` existentes (sin
  SQL nuevo).
- `GET /api/v1/read/overview|breakdown|customers|visitors|visitors/:vid` — las mismas funciones de
  stats del dashboard, ahora accesibles con API key en vez de cookie. Aceptan los mismos query params
  de rango/filtros (`?range=30d`, `?filters=...`).
- `POST /api/v1/events` — ingesta genérica. `name` requerido; `type` default `external` (bloquea los
  tipos reservados `pageview`/`goal`/`outbound`). Con `visitor_id` real se ancla a su última sesión;
  sin él, visitante sintético `ext:<platform|name>`. `value` + `props` se guardan como JSON (máx 1000).

Clave de implementación: `requireApiKey` resuelve el site desde la key y hace `c.set('site', site)`
—la misma variable que usa `loadSite`—, de modo que `makeCtx(c)` y las funciones de `stats.ts`
funcionan **sin modificarse**.

## Archivos modificados

- `src/worker/env.ts` — nuevos `siteFromApiKey()` y middleware `requireApiKey()` (import de tipos Hono).
- `src/worker/payments.ts` — se eliminó la copia privada de `siteFromApiKey` y se importa la compartida.
- `src/worker/events.ts` — **nuevo**: `handleEventApi` (ingesta genérica + visitante sintético).
- `src/worker/summary.ts` — **nuevo**: `handleSummaryApi` (compositor del resumen IA).
- `src/worker/index.ts` — registro de `/api/v1/events`, `/api/v1/summary`, `/api/v1/read/*` + middleware.
- `README.md` — nueva sección "Data API".

Sin migración: se optó por visitante sintético, el schema no cambió.

## Verificación hecha (worker local, D1 local)

- `npm run typecheck` limpio; `npm test` 37/37 verde.
- 401 sin key en `/summary` y `/events`; 200 con key.
- `/summary?range=30d` devuelve kpis + topSources/Channels/EntryPages.
- `POST /events` → `{ok:true, visitor_id:"ext:linkedin", synthetic:true}`; fila en `events` (type
  `external`, props con value) y sesión sintética `ext:linkedin` (source `external`, channel `External`).
- `/read/breakdown?dim=source` y `/read/overview` 200; `/api/sites` sigue devolviendo 401 (dashboard
  protegido intacto).
